# FTP 自动监控与上传功能指南

## 功能概述

本功能为 `DeviceLogListView` 页面提供了 FTP 服务器文件自动监控和上传能力。当 FTP 服务器的 `/logs` 目录中出现新文件时（无论是通过 FTP 客户端上传还是直接放入），系统可以自动检测并触发上传到日志服务器的操作。

## 功能特性

### 1. 自动文件监控
- **轮询机制**：定期检查 FTP 服务器上的文件列表
- **新文件检测**：通过文件路径、大小和修改时间的组合唯一标识文件
- **智能对比**：自动识别新增的文件

### 2. 可配置参数
- **监控间隔**：支持 5-300 秒可调，默认 30 秒
- **自动上传开关**：可以选择只监控不上传，或监控并自动上传
- **实时控制**：支持随时启动/停止监控

### 3. 用户界面
- **监控控制面板**：直观的开关按钮和状态指示
- **进度显示**：实时显示上传进度
- **状态反馈**：通过消息提示和日志记录监控状态

## 使用方法

### 启动自动监控

1. 打开设备日志页面
2. 在监控控制面板中配置监控间隔（可选）
3. 确认"自动上传"开关状态
4. 点击"启动监控"按钮

### 配置选项

#### 检查间隔
- **范围**：5-300 秒
- **默认值**：30 秒
- **建议**：
  - 对于频繁更新的场景，设置为 10-30 秒
  - 对于低频更新的场景，设置为 60-180 秒
  - 注意：间隔越短，网络和 FTP 服务器负载越高

#### 自动上传
- **开启**：检测到新文件后自动上传到日志服务器
- **关闭**：只监控不上传，仅在界面上显示新文件

### 停止监控

点击"停止监控"按钮即可停止自动监控功能。

## 工作原理

### 文件检测机制

系统使用以下算法识别新文件：

```typescript
const fileKey = `${file.path}_${file.size}_${file.modifiedTime.getTime()}`
```

每个文件通过以下三个属性的组合生成唯一标识：
- **文件路径**：确保不同目录的同名文件可区分
- **文件大小**：用于快速判断文件是否发生变化
- **修改时间**：精确到毫秒，确保同名同大小文件可区分

### 监控流程

1. **初始化**：启动监控时获取当前文件列表作为基准
2. **定时检查**：按配置的间隔定期获取最新文件列表
3. **对比分析**：将最新列表与上一次记录对比，找出新文件
4. **自动处理**：如果启用自动上传，依次上传所有新文件
5. **状态更新**：更新文件记录，为下一次检查做准备

### 上传流程

检测到新文件后，系统会自动：

1. 从 FTP 服务器下载文件到本地临时目录
2. 验证文件格式和大小（支持 .tgz 和 .tar.gz，最大 1GB）
3. 自动识别日志类型（protocol/oam_antenna/full）
4. 上传到日志服务器（`http://172.16.9.224:8085/api/v1/logs/upload`）
5. 实时显示上传进度
6. 上传完成后清理临时文件

## 日志类型自动识别

系统会根据文件名自动判断日志类型：

- **协议栈日志 (protocol/stack)**：文件名包含 "stack" 关键字
- **OAM与天线日志 (oam_antenna)**：文件名包含 "om" 或 "oam" 关键字
- **完整日志 (full)**：文件名同时包含 "stack" 和 "oam" 关键字

## 注意事项

### 1. 网络要求
- 确保能够访问 FTP 服务器（默认端口 10002）
- 确保能够访问日志服务器（http://172.16.9.224:8085）
- 建议在稳定的网络环境下使用

### 2. 性能考虑
- 监控间隔不宜设置过短（建议 ≥ 10 秒）
- 大文件上传会占用较多带宽和时间
- 同时上传多个文件时会串行处理，请耐心等待

### 3. 文件限制
- 支持格式：`.tgz`、`.tar.gz`
- 最大大小：1GB
- 文件名不能包含路径分隔符（`/` 或 `\`）

### 4. 错误处理
- 如果某个文件上传失败，不会影响其他文件的上传
- 所有错误都会记录到控制台，便于调试
- 建议关注浏览器控制台的 `[AutoMonitor]` 标签日志

## 故障排查

### 问题：监控启动失败
**可能原因**：
- FTP 服务器不可访问
- IP 地址配置错误

**解决方法**：
1. 检查 FTP 配置（参考 `getFTPConfig` 函数）
2. 使用浏览器控制台查看错误日志
3. 手动点击"刷新"按钮测试 FTP 连接

### 问题：检测不到新文件
**可能原因**：
- 文件已存在于监控启动前
- 监控间隔过长

**解决方法**：
1. 停止监控后重新启动（会重置文件记录）
2. 缩短监控间隔
3. 查看控制台日志确认文件列表是否正确获取

### 问题：上传失败
**可能原因**：
- 日志服务器不可访问
- 文件格式不支持
- 文件过大

**解决方法**：
1. 检查日志服务器地址配置
2. 确认文件符合格式要求（.tgz 或 .tar.gz，≤1GB）
3. 查看控制台中的详细错误信息
